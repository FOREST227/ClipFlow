# ClipFlow 剪流

ClipFlow 是一款面向 macOS 的原生剪切板应用，强调“在鼠标附近呼出、快速找回、直接粘贴、隐私优先”。它希望把复制这件高频小事做得更快、更顺手，也更安心。

## 它适合谁

如果你经常在这些场景里来回复制内容，ClipFlow 会比较适合你：

- 在文档、浏览器、聊天工具、代码编辑器之间频繁切换
- 需要反复粘贴链接、文本、代码片段、截图或图片
- 想保留复制历史，但又不希望敏感内容被无差别长期保存
- 希望用状态栏和快捷键快速完成操作，而不是总打开一个大窗口

## 这款应用的优点

- 更快：按 `Option + V` 就能在鼠标附近呼出快捷面板，不打断当前工作流
- 更省事：双击条目即可回填并粘贴，不需要先打开主窗口慢慢找
- 更清楚：自动区分文本、链接、代码、图片、敏感内容等类型
- 更整洁：主窗口、状态栏菜单、快捷面板都尽量保持紧凑清晰
- 更安心：支持敏感内容遮罩、排除应用、暂停监听、自动过期
- 更像 macOS：提供状态栏入口、快捷呼出、系统粘贴链路和原生窗口体验

## 主要功能

- 快捷呼出面板：在鼠标附近显示最近历史，适合快速回贴
- 历史内容管理：在主窗口里查看、筛选、整理已复制内容
- 合并主窗口：顶部切换“剪贴历史”和“设置”；菜单栏入口与 `Command + ,` 会在同一个窗口中选中对应页面，切换时保留未保存的排除规则草稿
- 外观模式：设置 → 通用中可选择浅色、深色或跟随系统，并在重启后保留选择。手动切换时，仅实际颜色发生变化才播放平滑过渡；切到相同颜色的“跟随系统”不播放动画
- 类型识别：自动识别链接、文本、代码、图片等内容
- 图片支持：可记录复制的图片，并展示缩略图和尺寸信息
- 链接直达：识别为链接时，可直接用默认浏览器打开
- 状态栏菜单：从菜单栏快速查看最近内容和常用操作
- 中文界面：主窗口、设置页、状态栏菜单、快捷面板均已中文化
- 自定义全局快捷键：在设置的“快捷键”区域点击当前组合，按下新组合立即保存；支持恢复默认 `Option + V`
- iCloud 同步开关：可同步普通历史内容，敏感内容默认保留本地

## 如何开始使用

1. 打开 ClipFlow
2. 在任意应用里复制一段文本、链接或图片
3. 按 `Option + V`（或设置中的自定义快捷键）呼出快捷面板
4. 选择需要的内容并直接粘贴

如果你更喜欢完整视图，也可以从状态栏或主窗口里浏览历史内容。

## 使用提醒

- 第一次使用自动粘贴时，macOS 可能会请求“辅助功能”权限
- “启动时打开菜单栏面板”开启时，启动或再次打开 App 会展开菜单栏弹窗；关闭时打开剪贴历史。设置页只在手动选择“设置”或按 `Command + ,` 时显示，不随启动自动恢复
- 快捷键至少包含 Command、Option、Control 中的一个，可额外加 Shift；录入时按 Esc、点击其他位置或切换应用可取消。系统保留组合可能无法录入，注册失败不会覆盖原设置；`Command + V` 保留给自动粘贴，不能用作呼出快捷键
- 如果没有授予该权限，ClipFlow 仍然可以记录历史，但无法自动把内容粘贴回目标输入框
- 设置中的“敏感内容 5 分钟后自动删除”默认开启，按复制时间计算，置顶也会过期。关闭后仍遮罩显示、仅本地保存；重新开启时会清理已超时的敏感记录
- 文稿目录同步将普通历史镜像到“文稿/ClipFlow”；只有系统开启 iCloud Drive 的“桌面与文稿文件夹”同步时，才会随系统同步到其他设备
- 为避免误删其他设备尚未同步完成的图片，文稿同步目录暂不自动清理未引用的图片文件；本地历史图片仍会随删除或过期清理
- 如果历史文件损坏或无法读取，应用会保留原文件和图片，并在设置中提示；恢复前的新记录仅暂存于内存

## 简要技术说明

ClipFlow 使用 SwiftUI 和 AppKit 构建，重点接入了 macOS 的剪切板、状态栏、快捷键、窗口与辅助功能相关能力。整体技术目标不是堆功能，而是尽量让应用在交互上更接近原生系统工具。

## 本地运行

开发需要 Swift 6 和完整 Xcode；最低运行系统为 macOS 12。macOS 12 的开机启动需在系统“用户与群组 → 登录项”中手动添加，macOS 13 及以上可在应用内管理。

```bash
swift build
swift run ClipFlowApp
```

运行回归测试需要包含 XCTest 的完整 Xcode：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

## 构建应用

本机首次构建前，创建固定自签名身份：

```bash
zsh scripts/setup_signing.sh
```

证书为 `ClipFlow Local Development`，有效期 10 年，私钥保存在登录钥匙串。
脚本重复执行会复用原身份；构建过程不会生成新证书或静默退回临时签名。
公钥证书及指纹配置保存在 `~/Library/Application Support/ClipFlow/signing/`，不包含私钥。

```bash
./scripts/build_app.sh
open dist/ClipFlow.app
```

日常使用请将构建后的应用替换安装到固定位置 `/Applications/ClipFlow.app`，并从该位置启动。
从旧的临时签名切换到固定签名后，可能需要重新授予一次辅助功能等权限；之后保持同一证书、`com.clipflow.app` 标识和安装路径，便可维持稳定的代码身份。
系统重置隐私设置、证书更换或权限规则变化仍可能要求重新授权。

请在“钥匙串访问”中妥善备份该证书及私钥（加密的 `.p12`），不要提交到仓库。
换电脑时应导入原身份；重新创建同名证书并不等于同一身份。
也可用 `CLIPFLOW_SIGNING_IDENTITY` 指定已有代码签名证书的 40 位 SHA-1 指纹。

GitHub 托管构建机没有本机私钥，因此现有发布流程显式使用 `CLIPFLOW_ADHOC_SIGN=1`。
该 CI 产物仍为临时签名，不具备上述本机固定签名的权限连续性；本机常规构建不要设置此变量。

生成三种架构的安装包：

```bash
zsh scripts/build_release_dmg.sh v0.0.5
```
